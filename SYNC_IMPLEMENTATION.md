1. Acesse https://console.cloud.google.com/apis/credentials
2. Crie um projeto (ou use existente)
3. Vá em "Credentials" → "Create Credentials" → "OAuth 2.0 Client ID"
4. Tipo: **Web application**
5. Authorized redirect URIs:
   ```
   http://localhost:3000/auth/callback
   https://tempest.vercel.app/auth/callback
   ```

## 🔍 Arquitetura Implementada

### Data Flow (Phase 1.0: Upload Only)

```
┌─────────────────┐
│ User Actions    │
│ (Settings)      │
└────────┬────────┘
         │
         ▼
┌─────────────────┐      ┌──────────────┐
│ SyncCard        │─────▶│ AuthDialog   │
│ - Connect btn   │      │ - AuthForm   │
│ - Status badge  │      └──────┬───────┘
└─────────────────┘             │
         │                      │ Google OAuth
         │                      ▼
         │              ┌──────────────┐
         │              │ /auth/callback│
         │              └──────┬───────┘
         │                     │
         ▼                     ▼
┌─────────────────────────────────────┐
│ SyncManager.uploadInitialData()     │
│ 1. Categories → AWS                 │
│ 2. CreditCards → AWS                │
│ 3. MonthlyData → AWS                │
│ 4. Incomes → AWS (FK: MonthlyData)  │
│ 5. Expenses → AWS (FK: Month+Cat)   │
│ 6. Installments → AWS (FK: Card)    │
└─────────────────┬───────────────────┘
                  │
                  ▼
         ┌────────────────┐
         │ SyncStore      │
         │ - idMappings   │ ← Persisted to localStorage
         │ - status       │
         │ - userEmail    │
         └────────────────┘
```

### ID Mapping Strategy

**Problema**: Zustand usa `id: 'mercado'` (kebab-case), Amplify auto-gera UUIDs.

**Solução**: Dual-field approach

```typescript
// Local (Zustand)
{ id: 'mercado', label: 'Mercado' }

// AWS (Amplify)
{
  id: 'uuid-123',           // Auto-generated by DynamoDB
  categoryId: 'mercado',    // Original kebab ID (for queries)
  label: 'Mercado'
}

// Mapping (SyncStore - persisted)
idMappings.categories = { 'mercado': 'uuid-123' }
```

**Uso**: Quando criar Expense, usar:

- `categoryId: 'mercado'` → Queries continuam funcionando
- `categoryCloudId: 'uuid-123'` → Foreign key para Category table

## 🚨 Limitações Conhecidas (Phase 1.0)

### ❌ Não Implementado (Phase 1.1+)

- **Download**: Não baixa dados da cloud para local
- **Merge**: Não resolve conflitos entre local e cloud
- **Sync Contínuo**: Não sincroniza mudanças automaticamente
- **Multi-Device Real**: Segundo device não baixa dados do primeiro

### ⚠️ Edge Cases

- **Cloud já tem dados**: Mostra error, requer merge manual (Phase 1.1)
- **Token expirado**: Precisa relogin (não tratado ainda)
- **Sem internet**: Error state, sem retry automático
- **Upload interrompido**: Não tem rollback (dados podem ficar incompletos)

### 🔧 Melhorias Futuras

- Progress indicator durante upload (chunks de 100)
- Retry com exponential backoff
- Rollback em caso de erro parcial
- Timestamps (createdAt, updatedAt) para merge
- GraphQL subscriptions (real-time)
